# Интернет-магазин API

REST API магазина на Django и DRF: регистрация и JWT, каталог товаров, персональная корзина, тестовое пополнение баланса и покупка товаров. Данные хранятся в PostgreSQL, успешные заказы логируются в консоль контейнера. Интерфейс магазина не требуется.

## Запуск

Нужны Docker и Docker Compose. Из каталога проекта:

```bash
docker compose up --build
```

Если порт 8000 уже занят, измените левую часть сопоставления `8000:8000` в `docker-compose.yml`, например на `8001:8000`, и используйте соответствующий порт в адресах.

Приложение ждёт готовности PostgreSQL и применяет миграции автоматически. API доступен на http://localhost:8000/api/, интерактивная документация — http://localhost:8000/api/docs/, OpenAPI-схема — http://localhost:8000/api/schema/. Данные PostgreSQL сохраняются в Docker volume. Остановка: `docker compose down`; для удаления также данных: `docker compose down -v`.

В `.env` находятся исключительно демонстрационные значения для локального запуска. Для реального развёртывания необходимо заменить секреты, отключить `DJANGO_DEBUG`, задать допустимые хосты, настроить HTTPS и безопасную инфраструктуру. Пополнение баланса здесь учебное и не подключено к платёжной системе.

Создать администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

Используйте имя и пароль этого пользователя для получения JWT. Администратор (пользователь с `is_staff`) может создавать, редактировать и удалять товары через API; остальные могут читать активные товары без авторизации. Неактивные товары видны только администраторам и не могут быть заказаны.

## API

Защищённые запросы передают заголовок `Authorization: Bearer <access>`. Суммы передаются строками с двумя знаками после запятой. Стандартные ошибки валидации возвращаются с HTTP 400, отсутствие доступа — 401/403, чужие объекты — 404.

| Метод и путь | Назначение | Пример тела JSON |
|---|---|---|
| `POST /api/auth/register/` | Регистрация | `{"username":"buyer","email":"buyer@example.com","password":"StrongPass123!"}` |
| `POST /api/auth/token/` | Получить access и refresh | `{"username":"buyer","password":"StrongPass123!"}` |
| `POST /api/auth/token/refresh/` | Обновить access | `{"refresh":"..."}` |
| `GET /api/profile/` | Профиль и баланс | — |
| `POST /api/profile/top-up/` | Пополнить баланс | `{"amount":"100.00"}` |
| `GET /api/products/` | Каталог с пагинацией | — |
| `GET /api/products/{id}/` | Товар | — |
| `POST /api/products/` | Создать товар, администратор | `{"name":"Книга","description":"Описание","price":"12.50","stock":5}` |
| `PATCH /api/products/{id}/` | Изменить товар, администратор | `{"stock":10}` |
| `DELETE /api/products/{id}/` | Удалить товар, администратор | — |
| `GET /api/cart/` | Текущая корзина | — |
| `POST /api/cart/` | Добавить товар; повторное добавление увеличивает количество | `{"product_id":1,"quantity":2}` |
| `PATCH /api/cart/{id}/` | Установить количество позиции | `{"quantity":3}` |
| `DELETE /api/cart/{id}/` | Удалить позицию | — |
| `POST /api/orders/` | Создать заказ из корзины | `{}` |
| `GET /api/orders/` | История своих заказов с пагинацией | — |
| `GET /api/orders/{id}/` | Свой заказ | — |

Заказ фиксирует название и цену товара на момент покупки. В одной транзакции блокируются пользователь и товары (в порядке ID), проверяются доступность, остатки и баланс, создаётся заказ, списываются средства и остатки, очищается корзина. При ошибке изменений нет. Цена и остаток проверяются при заказе, а не резервируются при добавлении в корзину. Успешный заказ логируется после фиксации транзакции; уведомление не является гарантированной очередью доставки. Удаление товара убирает его из корзин, но снимки в существующих заказах сохраняются.

## Проверка

```bash
docker compose exec web python manage.py test
```

Тесты проверяют JWT, права доступа, валидацию, корзину, успешный заказ, откаты при ошибках и параллельную покупку последнего товара в PostgreSQL. Посмотреть уведомления: `docker compose logs web`. Django admin доступен по `/admin/`.
